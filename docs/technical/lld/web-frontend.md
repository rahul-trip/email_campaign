# Web frontend (web2)

**Code:** `web2/` · **Layer:** client (talks only to the API) · **Tests:** `web2/e2e/*.spec.ts` (Playwright), `npm run typecheck`

## Purpose

`web2` is the operator's application: a single-page React app, built to static files and served by the API from `web2/dist`. It turns the API into screens for every operator task, follows the Stitch design system ([design.md](../../design.md)), and includes a guided tour that a test keeps in step with the screens. `web2` replaced the first app, `web/`, which is no longer served ([ADR 0014](../adr/0014-web2-replaces-web.md)).

## Responsibilities

- Thirteen screens (below), a sign-in page, and the layout shell (navigation, status chips, banners).
- Call the API through a client generated from its OpenAPI document. Send the CSRF header; react to sign-out.
- Poll where state changes without the user acting (runs, the review queue).
- Show server problems (problem details) as readable messages, and field errors next to their fields.
- The guided tour.

**Not its job:** any rule or check. Everything the screens enforce is enforced again by the API ([safety model](../hld/safety-model.md), principle 2).

## How it works

### Talking to the API

```ts
const leads = useQuery({
  queryKey: ["companies", search],
  queryFn: () => ok(client.GET("/api/companies", { params: { query: search } })),
});
```

- **Every request** gets `X-Requested-With: outbound` (middleware in `client.ts`), so writes pass the server's CSRF check.
- **`ok()`** returns the data, or throws `ApiProblem(status, code, detail, fields)` from the problem-details body. `Problem` and `Field` render it.
- **A 401** from any request except `/api/auth/login` and `/api/auth/me` dispatches `outbound:signed-out`. The layout then refetches `["me"]` and shows the sign-in page. Sign-out clears the whole query cache.
- **Writes** are `useMutation`s that invalidate the affected query keys on success; there are no optimistic updates. Edits to a lead or message send the `row_version` they read. A `409` (`isConflict`) tells the user the record changed and reloads it.
- **Uploads** use `multipart()` and `asUpload()`, because `openapi-typescript` types a file as a string.

### Polling

| What | Interval |
|---|---|
| Status (layout, dashboard) | 5 s |
| Rows waiting for a website decision | 15 s |
| Runs (layout, Runs screen) | 2 s while one is queued or running, else 10 s |
| Review queue, Needs attention | 10 s |
| Leads list | 15 s (keeps the previous page while loading) |

A run still `queued` 45 s after it was created shows a "worker stuck" warning, because the worker is probably not running.

### Constraints from the server

- **No inlined assets.** The CSP allows scripts, styles and fonts only from the same origin (`img-src` also allows `data:`). So `vite.config.ts` sets `assetsInlineLimit: 0`, no CDN is used, and fonts are bundled.
- **Routing.** The server returns `index.html` for unknown non-API paths, so client-side routes work on reload. An unknown `/api/...` path returns a JSON 404, never the app shell.

### The guided tour

- **Content.** `steps.ts` holds sections (welcome, targets, runs, review, attention, leads, journey, lead, reports, settings, compliance). Each has a place (a route, or `lead` and `journey`, which open the newest lead) and steps with an optional `target`.
- **Behaviour.** `Tour.tsx` opens automatically on the first visit (`localStorage["outbound.tour"]`). It navigates to each section and highlights the first visible `[data-tour=<target>]` element, re-measuring every 250 ms. Next, Back, Skip section and End tour are always available, and it can be restarted from the header.
- **The rule** ([CLAUDE.md](../../../CLAUDE.md)): a PR that adds or changes a screen, a button or a flow updates `steps.ts`, marks the element with `data-tour="name"` (or `tour="name"` on a `Card` or `Tabs`), and updates the manual's "Guided tour" section. `e2e/tour.spec.ts` fails when a step points at something that does not exist.

## Building and developing

| Task | Command |
|---|---|
| Develop against a local API | `cd web2 && npm run dev`: port 5174, proxies `/api` to `:8000` |
| Develop against fake vendors | `uv run python -m scripts.e2e_server`, then `API_TARGET=http://127.0.0.1:8765 npm run dev` |
| Type-check and build | `npm run typecheck`, `npm run build` (writes `web2/dist`, which `outbound serve` serves) |
| Regenerate the API client | `npm run gen:api`: exports `web2/openapi.json` from the app (against a throwaway database) and regenerates `src/api/schema.ts`. CI fails if either is stale |
| Browser tests | `npx playwright test` |

**Playwright** runs against `scripts/e2e_server.py`: the real API and a real worker on a throwaway SQLite database, with the fake vendors from `tests/stages/world.py`, serving `web2/dist` on `:8765`. It uses one worker, no retries, and keeps traces on failure. `e2e/helpers.ts` fails a test on any page error, console error or 5xx response, and marks the tour as seen.

The production image builds `web2` in a Node 22 stage and copies `dist` into the Python image (`Dockerfile`).

## Invariants

- The client is generated from the server's own OpenAPI document; CI refuses a stale one.
- Every write carries the CSRF header.
- Status words and colours come only from `lib/status.ts`.
- Every tour step points at an element that exists.

## Security and privacy

- **Session.** The cookie is `HttpOnly`, so the app never reads it. Session state is the `["me"]` query.
- **Rendering.** Lead and email text is rendered as text, never as HTML; the strict CSP is the second line.
- **Browser storage.** Only whether the tour was seen, and the theme.

## Known limitations

- `lib/status.ts` cites a "design brief, Section 7" that does not exist ([R-19](../tech-debt-and-risks.md#r-19--p3--housekeeping-stale-references-and-inconsistent-versions)).
- The legacy `web/` is still built, tested and audited in CI, and Dependabot watches it instead of `web2/` ([R-16](../tech-debt-and-risks.md#r-16--p2--supply-chain-gaps-in-update-and-pinning-coverage)).
- The `web2` package version (0.1.0) is not tied to releases.

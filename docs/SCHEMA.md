# Schema v1 — Reference

This is the column-level spec for the outbound engine's database. The SQLAlchemy models in `outbound/db/models.py` and the first Alembic migration are written from it.

- Every schema change goes through an Alembic migration, and this file is updated in the same PR.
- A test checks that every `CHECK (... IN (...))` list matches the domain enum of the same name in `outbound/domain/enums.py`.

Schema v1 is meant to last through the SaaS move.
- **The SaaS alpha track** (Phases 6a–6g, [phases/phase-6-saas-ready.md](phases/phase-6-saas-ready.md)) adds tables and columns in migrations 0006–0013:
  - users, memberships, sessions;
  - plans, credits and usage;
  - encrypted credentials;
  - the verified lead directory.
- It turns `workspace_id` into a row-level-security key backed by composite foreign keys.
- Those changes are specified in the phase documents and land here, in this file, with each migration's PR.

---

## 1. Conventions (all tables)

- **`id`**: `TEXT PRIMARY KEY`, a UUIDv7 generated by the application. It sorts by creation time and maps to Postgres `uuid` later.
- **`workspace_id`**: `TEXT NOT NULL REFERENCES workspaces(id)` on every table except `workspaces`. It is indexed and comes first in every composite index.
- **Links between tenant tables match the workspace too** (migration 0007): a child's `(workspace_id, parent_id)` references the parent's `(workspace_id, id)`, and every parent has `UNIQUE (workspace_id, id)`. So the database refuses a row that points into another workspace. Each key keeps the name of the single-column key it replaced (`fk_<table>_<column>_<parent>`).
- **Row-level security** (migration 0009, Postgres only): see section 5b.
- **`created_at` and `updated_at`**: UTC, set by the data layer and never by callers. Append-only tables have only `created_at`. The `UtcDateTime` column type refuses naive datetimes and restores the UTC zone on SQLite, which drops it.
- **Column types**:
  - `TIMESTAMP` is ISO-8601 text in SQLite and `timestamptz` in Postgres.
  - `JSON` is text in SQLite and `jsonb` in Postgres.
  - `BOOLEAN` is 0/1 in SQLite.
- **Money**: integer micro-dollars in `BIGINT` columns named `*_micro_usd` (1 USD = 1,000,000), so amounts never go through float rounding. `BIGINT` because a 32-bit integer overflows at about $2,147.
- **Closed value sets**: `VARCHAR(40)` with one named `CHECK (... IN (...))` per column, never a native enum, so they behave the same on both databases. The model generates each check from the matching `StrEnum` in `outbound/domain/enums.py`, so code and database cannot disagree; a test also compares every constraint in the migrated database with its enum. The frozen migration spells the values out literally.
- **What goes in JSON**: only data that is never filtered or joined on. Anything a query filters on gets its own column.
- **Deletes**: `ON DELETE CASCADE` only from a parent to rows that cannot exist without it. In normal flow nothing is deleted; "forget" scrubs data instead.

The SQL blocks below leave out `id`, `workspace_id`, `created_at` and `updated_at`.

## 2. Relationships

```
workspaces 1─N  campaigns, mailboxes, country_policies, suppressions, import_batches,
                companies, runs, provider_calls, events   (every table carries workspace_id)
campaigns       1─N  companies
import_batches  1─N  import_rows  N─1 companies (nullable until accepted or merged)
companies       1─N  contacts, notes, messages, inbound_messages
contacts        1─N  contact_emails, consents, messages
contact_emails  1─N  messages          (the exact address each message used)
mailboxes       1─N  messages, inbound_messages
messages        1─N  inbound_messages  (what each reply answers)
messages.in_reply_to → previous touch's rfc_message_id (threading)
runs            1─N  provider_calls
events          → any row by (entity_type, entity_id)   — the only polymorphic link; history only
```

## 3. Uniqueness

| Rule | Enforced by |
|---|---|
| One company per root domain per workspace | `UNIQUE (workspace_id, domain)` on `companies` |
| One contact per LinkedIn profile | Partial unique index on `(workspace_id, linkedin_url)` where `linkedin_url` is not null |
| Each email address belongs to one contact | `UNIQUE (workspace_id, email)` on `contact_emails` |
| One primary email per contact | Partial unique index on `contact_id` where `is_primary` |
| One *live* message per touch per contact | Partial unique index `ux_messages_live_touch` on `(company_id, contact_id, step)` where `state NOT IN ('cancelled','rejected')`. A cancelled or rejected message does not block a new one (migration 0002) |
| One batch per webhook event | Partial unique index `ux_import_batches_webhook` on `(workspace_id, source, filename)` where `source = 'webhook'` (migration 0002) |
| Workspace slugs are unique; names may repeat | `UNIQUE (slug)` on `workspaces` (migration 0008, which dropped 0002's `UNIQUE (name)`) |
| One running pipeline run per workspace | Partial unique index `ux_runs_one_running_pipeline` on `(workspace_id)` where `status = 'running' AND kind = 'pipeline'` (migration 0006) |
| A sent or received message is stored once | Unique `rfc_message_id` per workspace |
| One suppression per value | `UNIQUE (workspace_id, kind, value_hash)` |
| One policy per country | `UNIQUE (workspace_id, country_code)` |

## 4. History, manual input, concurrency

- **Current value and history.** Each row holds the current value. Every change also writes an `events` row with type `field_changed` and data `{field, old, new, source}`.
- **Values that can be plural are child rows.** For example, an operator-given email and an engine-found email are two `contact_emails` rows, each with its own provenance and status; one of them is primary.
- **Operator input is protected.** When an operator sets a field, its name is added to that row's `manual_fields`. The repository rejects engine writes to those fields, but still records the engine's value as an event so the UI can show both values side by side.
- **Notes are append-only.**
- **Optimistic locking.** `companies` and `messages` carry a `row_version` (SQLAlchemy `version_id_col`). An update made against a stale version fails.
- **Forget** runs in one transaction (`outbound/services/forget.py`) and does not commit, so it succeeds or fails as a whole:
  1. Writes a hashed suppression entry, even for an address we do not hold, so it can never be imported later.
  2. Cancels the person's unsent messages (`generated`, `approved`, `drafted`) and returns the remote draft ids, which the caller deletes from the mailbox after the commit.
  3. Sets the contact to `forgotten`, then scrubs every personal field about them:
     - `contacts`: name, title, seniority and LinkedIn URL become NULL.
     - `contact_emails`: the address and its provider details become NULL.
     - `messages`: `subject` and `generated_body` become `[erased]` (they are required columns), while `final_body` and `snippets` become NULL.
     - `inbound_messages`: sender, excerpt and extracted data become NULL.
     - `consents.evidence` and any `notes` about the person (or mentioning their address) become `[erased]`.
     - `provider_calls.response` becomes NULL for calls about the contact.
     - `import_rows.raw` becomes `{"erased": true}` for any row mentioning the address.
     - `events.data` becomes `{"erased": true}` for the contact, their addresses and their messages.
  4. Moves the company to `suppressed` if nobody workable is left and its status allows it.
  5. Records a final `forgotten` event with no personal data.

  Rows, costs and the fact that things happened survive; the identifying detail does not. A test scans every text column of every table for the person's address and name.

## 5. Tables

### Tenancy and configuration

```sql
CREATE TABLE workspaces (
  id              TEXT PRIMARY KEY,
  name            TEXT NOT NULL,                  -- may repeat across workspaces
  slug            TEXT NOT NULL UNIQUE,           -- URL-safe, from the name (migration 0008)
  status          TEXT NOT NULL DEFAULT 'active'
                  CHECK (status IN ('active','paused','suspended','pending_deletion','deleted')),
                  -- moves only as the WORKSPACE state machine allows
  deletion_due_at TIMESTAMP,                      -- set while pending_deletion
  sender_profile  JSON NOT NULL,  -- legal name, postal address, registration no., narrative, value props, signature
  settings        JSON NOT NULL,  -- send_enabled (false), safe_to_send_only (true), budget_per_prospect_micro_usd,
                                  -- breaker {hard_per_100: 3, hard_per_24h: 2}, catch_all_resolver,
                                  -- reply_webhook_url, few_shot_examples (5), timezone
  created_at      TIMESTAMP NOT NULL,
  updated_at      TIMESTAMP NOT NULL
);

CREATE TABLE campaigns (
  name               TEXT NOT NULL,
  target_titles      JSON NOT NULL,                   -- ordered, most wanted first
  icp_description    TEXT,
  min_fit_score      INTEGER NOT NULL DEFAULT 60 CHECK (min_fit_score BETWEEN 0 AND 100),
  research_questions JSON NOT NULL DEFAULT '[]',      -- up to 3
  cadence_days       JSON NOT NULL DEFAULT '[0,3,8]', -- business-day offsets from touch 1: days 1, 4, 9
  status             TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','paused','archived')),
  UNIQUE (workspace_id, name)
);

CREATE TABLE mailboxes (
  address           TEXT NOT NULL,
  gateway           TEXT NOT NULL CHECK (gateway IN ('imap','emailengine','smartlead','instantly')),
  credentials_ref   TEXT NOT NULL,     -- name of the secret in the environment, never the secret
  sending_domain    TEXT NOT NULL,
  dns_check         JSON,              -- last SPF/DKIM/DMARC/isolation result with timestamp
  warmup_started_at TIMESTAMP,
  daily_cap         INTEGER NOT NULL DEFAULT 10,
  status            TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','paused','error')),
  UNIQUE (workspace_id, address)
);

CREATE TABLE country_policies (
  country_code       TEXT NOT NULL CHECK (length(country_code) = 2),  -- ISO 3166-1 alpha-2; 'ZZ' = unknown
  rule               TEXT NOT NULL CHECK (rule IN ('allow','allow_with_footer','consent_required','block')),
  requires_corporate_subscriber BOOLEAN NOT NULL DEFAULT FALSE,     -- true for GB
  allowed_provenance JSON,                                           -- CA: ["operator_given","publicly_published"]
  footer_template    TEXT,
  version            INTEGER NOT NULL DEFAULT 1,                     -- bumped on every change; stored on each decision
  reviewed_by        TEXT,
  reviewed_at        TIMESTAMP,
  UNIQUE (workspace_id, country_code)
);

CREATE TABLE suppressions (
  kind        TEXT NOT NULL CHECK (kind IN ('email','domain')),
  value_hash  TEXT NOT NULL,   -- sha256(lower(trim(value))); the value itself is never stored
  reason      TEXT NOT NULL CHECK (reason IN ('opt_out','manual','hard_bounce','complaint','forget')),
  UNIQUE (workspace_id, kind, value_hash)
);
```

### Accounts and people

```sql
CREATE TABLE companies (
  campaign_id       TEXT REFERENCES campaigns(id),
  domain            TEXT NOT NULL,                 -- registrable root domain
  name              TEXT,
  country_code      TEXT CHECK (length(country_code) = 2),
  legal_entity_type TEXT NOT NULL DEFAULT 'unknown'
                    CHECK (legal_entity_type IN ('corporate_subscriber','sole_trader_or_partnership','unknown')),
  source            TEXT NOT NULL CHECK (source IN ('manual','discovery','import','referral')),
  priority          INTEGER NOT NULL DEFAULT 5,    -- 1 = highest
  status            TEXT NOT NULL CHECK (status IN ('new','researched','qualified','disqualified','contacts_found',
                      'email_ready','held','copy_ready','approved','rejected','in_sequence','replied',
                      'completed','suppressed','failed')),
  hold_reason       TEXT CHECK (hold_reason IN ('catch_all_unverified','catch_all_resolving','consent_required',
                      'country_unknown','entity_unknown','needs_operator')),
  failed_stage      TEXT,
  last_error        TEXT,
  attempts          INTEGER NOT NULL DEFAULT 0,
  next_action_at    TIMESTAMP,                     -- follow-up due, OOO snooze, soft-bounce retry, resolver poll
  fit_score         INTEGER CHECK (fit_score BETWEEN 0 AND 100),
  fit_reason        TEXT,
  email_pattern     TEXT,                          -- e.g. '{first}.{last}', cached once one address is valid
  research          JSON,                          -- summary, products, news, signals, hook candidates
  research_answers  JSON,                          -- answers to the campaign's questions
  policy_decision   JSON,                          -- rule, policy version, reasons, skipped
  policy_skip_from  TEXT CHECK (policy_skip_from IN ('gate','contacts','email','copy','deliver')),
                                                   -- the operator skipped the country rule from this stage on (migration 0004)
  manual_fields     JSON NOT NULL DEFAULT '[]',
  row_version       INTEGER NOT NULL DEFAULT 1,
  UNIQUE (workspace_id, domain)
);
CREATE INDEX ix_companies_queue ON companies (workspace_id, status, next_action_at);

CREATE TABLE contacts (
  company_id    TEXT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  full_name     TEXT,                              -- NULL after forget
  first_name    TEXT,
  last_name     TEXT,
  title         TEXT,
  seniority     TEXT,
  linkedin_url  TEXT,
  rank          INTEGER NOT NULL,                  -- 0 = referral, 1 = top choice
  source        TEXT NOT NULL CHECK (source IN ('operator','site','search','database','referral','ooo_alternate')),
  status        TEXT NOT NULL DEFAULT 'candidate'
                CHECK (status IN ('unconfirmed','candidate','active','bounced','referred_away','opted_out','forgotten')),
                -- unconfirmed (migration 0003): found by a public search whose employer did not
                -- clearly match the company; never worked on until the operator confirms them
  manual_fields JSON NOT NULL DEFAULT '[]'
);
CREATE UNIQUE INDEX ux_contacts_linkedin ON contacts (workspace_id, linkedin_url) WHERE linkedin_url IS NOT NULL;

CREATE TABLE contact_emails (
  contact_id     TEXT NOT NULL REFERENCES contacts(id) ON DELETE CASCADE,
  email          TEXT,                             -- NULL after forget
  status         TEXT NOT NULL DEFAULT 'unverified' CHECK (status IN ('unverified','valid','catch_all_resolved',
                   'catch_all_pending','catch_all_unverified','unknown','invalid')),
  provenance     TEXT NOT NULL CHECK (provenance IN ('operator_given','publicly_published','api_database',
                   'pattern_inferred','referral')),
  found_by       TEXT,                             -- provider name, or 'operator'
  verified_by    TEXT,
  resolution_ref TEXT,                             -- catch-all resolver job id while catch_all_pending
  verified_at    TIMESTAMP,
  is_primary     BOOLEAN NOT NULL DEFAULT FALSE,
  verification_skipped BOOLEAN NOT NULL DEFAULT FALSE, -- the operator writes to it without proof (migration 0005)
  UNIQUE (workspace_id, email)
);
CREATE UNIQUE INDEX ux_contact_emails_primary ON contact_emails (contact_id) WHERE is_primary;

CREATE TABLE notes (                               -- append-only
  company_id  TEXT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  contact_id  TEXT REFERENCES contacts(id),
  body        TEXT NOT NULL,
  source      TEXT NOT NULL CHECK (source IN ('operator','import','referral','reply','system')),
  author      TEXT
);

CREATE TABLE consents (
  contact_id    TEXT NOT NULL REFERENCES contacts(id) ON DELETE CASCADE,
  basis         TEXT NOT NULL CHECK (basis IN ('express','conspicuous_publication','voluntary_disclosure',
                  'existing_relationship')),
  evidence      TEXT NOT NULL,                     -- e.g. 'business card, Solar UK expo, 12 Oct 2026'
  recorded_by   TEXT NOT NULL,
  withdrawn_at  TIMESTAMP
);
```

### Outreach

```sql
CREATE TABLE messages (
  company_id        TEXT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  contact_id        TEXT NOT NULL REFERENCES contacts(id),
  contact_email_id  TEXT NOT NULL REFERENCES contact_emails(id),
  mailbox_id        TEXT REFERENCES mailboxes(id),
  step              INTEGER NOT NULL CHECK (step BETWEEN 0 AND 2),   -- 0 = touch 1
  subject           TEXT NOT NULL,

  final_body        TEXT,           -- after an operator edit, or as found in the Sent folder

);

CREATE UNIQUE INDEX ux_messages_rfc ON messages (workspace_id, rfc_message_id) WHERE rfc_message_id IS NOT NULL;

CREATE TABLE inbound_messages (
  mailbox_id      TEXT NOT NULL REFERENCES mailboxes(id),
  message_id      TEXT REFERENCES messages(id),
  company_id      TEXT REFERENCES companies(id),
  contact_id      TEXT REFERENCES contacts(id),
  rfc_message_id  TEXT NOT NULL,
  from_address    TEXT,           -- NULL after forget
  received_at     TIMESTAMP NOT NULL,
  body_excerpt    TEXT,
  category        TEXT NOT NULL CHECK (category IN ('positive','question','referral','out_of_office',
                    'unsubscribe','hard_bounce','soft_bounce','other')),
  confidence      REAL,
  extracted       JSON,           -- return date, referred person, DSN status code
  handled_at      TIMESTAMP,
  UNIQUE (workspace_id, rfc_message_id)
);
```

### Runs, cost and audit

`provider_calls` serves as the response cache, the cost ledger and the waterfall audit trail. `events` holds both the status log and the field history.

```sql
CREATE TABLE runs (
  kind             TEXT NOT NULL CHECK (kind IN ('pipeline','sync','import','bakeoff')),
  params           JSON,
  status           TEXT NOT NULL CHECK (status IN ('queued','running','succeeded','failed','cancelled')),
  counts           JSON,
  cost_micro_usd   BIGINT NOT NULL DEFAULT 0,
  started_at       TIMESTAMP,
  finished_at      TIMESTAMP,
  heartbeat_at     TIMESTAMP       -- touched between leads; a running run without one for 30
                                   -- minutes is failed by the worker (migration 0006)
);
CREATE UNIQUE INDEX ux_runs_one_running_pipeline ON runs (workspace_id)
  WHERE status = 'running' AND kind = 'pipeline';

CREATE TABLE provider_calls (     -- append-only
  run_id          TEXT REFERENCES runs(id),
  company_id      TEXT REFERENCES companies(id),
  contact_id      TEXT REFERENCES contacts(id),
  provider        TEXT NOT NULL,   -- 'tavily', 'orbisearch', 'myemailverifier', 'scrubby', 'llm', ...
  operation       TEXT NOT NULL,   -- 'search', 'extract', 'find_email', 'verify', 'resolve_catch_all', 'research', 'copy', 'classify'
  request_hash    TEXT NOT NULL,   -- sha256 of the normalised request
  outcome         TEXT NOT NULL CHECK (outcome IN ('hit','miss','error','cache_hit','blocked_by_cap')),
  response        JSON,            -- normalised; never secrets
  cost_micro_usd  BIGINT NOT NULL DEFAULT 0,
  latency_ms      INTEGER
);
CREATE INDEX ix_provider_calls_cache ON provider_calls (workspace_id, provider, operation, request_hash, created_at);
CREATE INDEX ix_provider_calls_spend ON provider_calls (workspace_id, created_at);

CREATE TABLE events (             -- append-only
  entity_type  TEXT NOT NULL CHECK (entity_type IN ('company','contact','contact_email','message','mailbox',
                 'workspace','import_row')),
  entity_id    TEXT NOT NULL,
  type         TEXT NOT NULL,      -- created, status_changed, field_changed, approved, edited, policy_decided, consent_recorded, consent_withdrawn, suppression_added, forgotten, legacy_imported
  actor        TEXT NOT NULL,      -- 'system', 'operator', 'provider:<name>'
  data         JSON NOT NULL       -- {from, to} or {field, old, new, source}
);
CREATE INDEX ix_events_entity ON events (workspace_id, entity_type, entity_id, created_at);
```

## 5b. Row-level security and roles (migration 0009, Postgres only)

| Role | Connects for | On tenant tables | On `workspaces` |
|---|---|---|---|
| owner (`postgres` on Supabase) | `db upgrade`, `seed` | everything (owners are not subject to row-level security) | everything |
| `outbound_app` | API and worker | SELECT, INSERT, UPDATE, DELETE, through policy `tenant_rows`: `workspace_id = current_setting('app.workspace_id', true)` | SELECT, UPDATE of its own row (`own_workspace`: `id = current_setting('app.workspace_id', true)`) |
| `outbound_platform` | the scheduler (later the admin console) | SELECT, through policy `platform_read` (`USING (true)`) | SELECT, INSERT, UPDATE (`platform_all`) |

- **How the setting is made.** `app.workspace_id` is set inside every transaction by a SQLAlchemy `after_begin` listener (`outbound/db/session.py`), using `set_config(..., true)`, so it never outlives the transaction on a pooled connection. Without it the app role sees no rows at all.
- **No `FORCE ROW LEVEL SECURITY`.** The owner must still migrate and seed. Instead, `serve` and `worker` refuse to start in production when connected as the owner, a superuser or a BYPASSRLS role (`outbound/db/isolation.py`).
- **Supabase's `anon` and `authenticated`** roles have every grant revoked, which closes the Data API.
- **No `alembic_version` grant** goes to the two roles.

## 6. Safe-to-send rule (domain, not SQL)

A message may be drafted or sent only when **all** of the following hold:

1. `contact_emails.status IN ('valid','catch_all_resolved')`, or `contact_emails.verification_skipped` (the operator skipped the check; approval then needs an explicit acknowledgement). `catch_all_unverified` is also allowed, but only if `settings.safe_to_send_only` is false.
2. Neither the email nor its domain hash is in `suppressions`.
3. The company's country policy allows it under the current policy version:
   - for GB, `legal_entity_type = 'corporate_subscriber'`;
   - for a country with `allowed_provenance` (such as CA), the email's provenance is in that list;
   - for `consent_required`, the contact has an active `consents` row.
4. The contact's status is `candidate` or `active`.

## 7. Value conventions the code relies on

Migrations 0006–0009 (Phase 6a) are described above: the run heartbeat and lock, tenant-bound foreign keys, workspace slug and status, and row-level security. Phases 2 and 3 added no tables or columns; migration 0002 (Phase 3b) only changed uniqueness rules, listed in section 3, migration 0003 added `unconfirmed` to `contacts.status`, migration 0004 added `companies.policy_skip_from`, and migration 0005 added `contact_emails.verification_skipped`. The workspace settings `country_policy_enabled` and `footer_enabled` (both default true) live in `workspaces.settings`. They did fix how some columns are used; these conventions are part of the schema contract.

| Column | Convention |
|---|---|
| `companies.research` | Keys written by the research stage: `summary`, `products`, `news`, `hooks`, `hiring`, `tech`, `pages` (URLs read), `thin` (true when the site could not be read and search results stood in), `country_evidence`, `legal_evidence`, `workers`, and `site_emails` (addresses on the company's own domain found in its pages; the email stage tries a matching one first) |
| `companies.policy_decision` | `{outcome, rule, hold_reason, policy_version, reasons}` as written by the gate, or by the email stage when the chosen address's provenance changes the outcome |
| `companies.next_action_at` | Also the retry back-off for `failed` leads (15 minutes times attempts) and the wake-up time for `catch_all_resolving` holds (six hours) |
| `contact_emails` | Every address the waterfall checks is saved, including `invalid` ones, so none is ever verified twice. `resolution_ref` holds an asynchronous resolver's job id while the status is `catch_all_pending` |
| `messages.remote_draft_id` | `<{message id}.outbound@{mailbox domain}>`, the draft's own Message-ID. Delivery asks the mailbox for it before saving, which makes drafting idempotent |
| `messages.final_body`, `edit_distance` | Set at review when the operator edits (`edit_distance` 0 to 1, whitespace ignored), and overwritten by the Sent sync with the body that actually went out, measured against `generated_body` |
| `import_batches.filename` | For webhook batches, `webhook:{event_id}`; a second request with the same event id is answered as a duplicate and creates nothing |
| `runs.status` | `queued` (made by the API), `running` (claimed by the worker), then `succeeded`, `failed` or `cancelled`. A run cancelled while running stays `cancelled` when it finishes. `runs.counts` is `{stage: {outcome: n}}`, or `{"error": ...}` for a run that failed outright |
| `mailboxes.dns_check` | `{domain, ok, spf, dkim, dmarc}`, each check `{name, ok, detail, record}` |
| `workspaces.settings` | Editable from the app: `safe_to_send_only`, `budget_per_prospect_micro_usd`, `few_shot_examples`, `timezone`. `send_enabled` cannot be switched on before Phase 5. The webhook secret is not stored here: it is the environment setting `INTAKE_WEBHOOK_SECRET` |
